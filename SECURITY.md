# Security Policy

## Reporting a Vulnerability

We take security issues in TIN Validator seriously.

If you believe you have discovered a security vulnerability, please report it
responsibly and do not disclose the vulnerability publicly until it has been
reviewed.

Please include, where possible:

- A description of the vulnerability
- The affected component and version
- Steps to reproduce the issue
- The potential security impact
- Any suggested mitigation or fix

Please do **not** include:

- Personal data
- Production credentials
- API keys, passwords or access tokens
- Confidential customer information
- Other sensitive information that is not required to demonstrate the issue

Security vulnerabilities should not be reported through a public GitHub issue.

Please use the security reporting mechanism provided for this repository, such
as GitHub's private vulnerability reporting feature, where available.

## Response and Support

This project is maintained on a best-effort basis.

Neither the project maintainers nor Captin B.V. guarantee a specific response
time, resolution time, security update schedule or continued support for any
particular version.

Where appropriate, confirmed security vulnerabilities may be addressed through
a code change or new release.

## Supported Versions

Unless explicitly stated otherwise, only the latest version of the project
should be considered for security fixes.

Older versions may not receive security updates.

## Scope

Security reports should relate directly to the TIN Validator source code,
dependencies or its documented use.

Please note that incorrect or outdated TIN validation rules are generally
considered functional correctness issues rather than security vulnerabilities.

TIN Validator performs technical validation of TIN formats, structures and
checksums. It does not verify the identity of a person or organisation, confirm
that a TIN has actually been issued, or perform KYC, AML, FATCA, CRS or other
regulatory compliance checks.

## Disclosure

We ask security researchers to allow reasonable time for investigation and,
where appropriate, remediation before publicly disclosing a vulnerability.

Please avoid accessing, modifying or deleting data belonging to others when
researching a potential vulnerability.
